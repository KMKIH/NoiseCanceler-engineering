# Timeline과 FMOD 재생 위치 측정 기록

## 초기 측정

Unity 6000.0.67f1에서 챕터 5-2 개발 씬(`Ch5Ep2_Dev`)을 에디터 배치 모드로 실행했다. 각 조건을 FMOD 재생 위치 115초까지 3회 실행하고 프레임 끝에서 두 위치를 다시 읽었다.

| 방식 | 평균 절대 차이 | 95백분위 | 최대 |
| --- | ---: | ---: | ---: |
| 기본 FMOD Event Track | 120.505ms | 134.328ms | 142.567ms |
| 별도 재생 + 주기 보정 | 7.241ms | 16.574ms | 148.275ms |

기본 트랙 조건에서는 트랙이 생성한 인스턴스의 위치를 읽고 주기 보정을 껐다. 다른 게임 로직이 참조하던 별도 인스턴스는 음소거 상태로 유지했다. Timeline이 앞선 시간은 FMOD 재생 1~5초 구간에서 평균 120.033ms, 100~110초 구간에서 121.527ms였다.

## DSPClock에서의 재생 방식과 Stream 설정 비교

열려 있는 Unity 에디터의 Game View에서 `Ch5Ep2`를 실행했다. 시작 연출을 건너뛰고 판정 이벤트 리스너를 제거했다. 각 조건에서 같은 곡을 115초씩 3회 재생하고 카메라 렌더링 콜백을 확인했다. Stream 켬과 끔은 별도 세션에서 측정했다.

- **재생 준비** — 매 회차 이벤트의 `isStream` 값을 확인했다. 두 설정 모두 FMOD 샘플 로드 상태가 `LOADED`가 되고 프리로드 작업이 끝날 때까지 기다렸다. Stream을 켠 경우에는 재생 중에도 데이터를 읽는다.
- **재생 경로** — Custom FMOD Event Track은 클립 진입 시 생성한 인스턴스를 사용했다. 별도 재생 조건에서는 테스트 코드가 Timeline 시작 직후 `PlaySong()`을 호출했다.
- **측정 순서** — `DataManager.CustomUpdate()`가 FMOD 위치를 읽고, 이어서 `PlayManager.CustomUpdate()`가 별도 재생 조건에서 250ms마다 두 위치를 확인해 차이가 20ms를 넘을 때 Timeline을 보정했다. 두 재생 방식 모두 같은 코드 위치에서 FMOD 시각을 다시 읽어 음악 시작 오프셋을 반영한 Timeline 시각과 비교했다.
- **집계** — 아래 통계는 세 회차의 프레임 샘플을 합쳐 구했다. 95백분위는 전체 샘플 중 95%가 해당 값 이하였다는 뜻이다.

| Stream | 재생 방식 | 샘플 수 | 평균 절대 차이 (ms) | 95백분위 (ms) | 최대 (ms) |
| --- | --- | ---: | ---: | ---: | ---: |
| 켬 | Custom FMOD Event Track | 20,697 | 110.405 | 122.352 | 133.768 |
| 끔 | Custom FMOD Event Track | 20,730 | 39.814 | 51.388 | 652.026 |
| 켬 | 별도 재생 + 주기 보정 | 20,682 | 6.448 | 14.533 | 109.545 |
| 끔 | 별도 재생 + 주기 보정 | 20,122 | 8.172 | 21.459 | 64.000 |

Custom FMOD Event Track + DSPClock에서 Stream을 켜면 세 회차 모두 Timeline이 앞섰다. 재생 1~5초와 100~110초 구간의 회차별 평균은 모두 약 108~114ms였다. Stream을 끈 조건에서는 첫 회차의 111.136초 지점에서 652.026ms까지 차이가 벌어졌다. 다른 두 회차의 최대값은 44.220ms와 51.739ms였다. 이 로그만으로 첫 회차의 급증 원인을 특정하기는 어렵다.

별도 재생 + DSPClock에서 Stream을 끈 세 회차의 평균 프레임률은 각각 40.14, 74.92, 59.88fps였다. 이 조건은 회차별 실행 환경에도 차이가 있어 평균의 작은 차이를 Stream만의 효과로 해석하기 어렵다.
