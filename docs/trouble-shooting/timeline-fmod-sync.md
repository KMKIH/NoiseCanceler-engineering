# Timeline 연출과 FMOD 음원 사이의 싱크 개선

## 문제 상황

리듬게임의 음악에 맞춰 배경 애니메이션과 화면 효과를 실행하기 위해 Unity Timeline을 사용했다. 초기에는 Timeline의 Audio Track에서 음악과 연출을 함께 재생했지만, 실행할 때마다 두 요소의 시작 시점이 일정하게 맞지 않는 문제가 발생했다.

리듬게임에서는 작은 시간 차이도 쉽게 체감되기 때문에 음악 재생과 연출 실행 구조를 분리하기로 했다.

## 음악과 연출 분리

Timeline에서는 음악을 제거하고 연출 실행 시점만 관리하도록 변경했다. 실제 음악의 로드와 재생은 FMOD에서 담당하게 했다.

```text
Unity Timeline  → 화면 연출
FMOD            → 음악 재생
```

하지만 두 시스템을 코드에서 각각 시작하면 호출 순서와 준비 상태에 따라 시작 시점이 다시 어긋날 수 있었다. 이를 줄이기 위해 게임 시작 전에 FMOD 음원을 미리 로드하고, Timeline의 0초 지점에 배치한 Signal에서 음악을 재생하도록 구성했다.

```text
FMOD 음원 사전 로드
        ↓
Timeline 재생
        ↓
0초 Signal 발생
        ↓
FMOD 음원 재생
```

이 구조를 통해 음악 재생 준비에 따른 초기 지연을 줄이고, 음악 시작 명령이 Timeline의 시작 흐름 안에서 한 번만 실행되도록 했다.

## 재생 직후 강제 보정 문제

처음에는 Timeline과 FMOD를 시작한 직후 두 시스템의 시간을 강제로 맞추는 방법을 시도했다. 그러나 이미 재생이 시작된 상태에서 시간을 이동하면 음원이나 연출의 초반부가 생략될 수 있었다.

따라서 재생 직후 시간을 강제로 이동하는 방법은 사용하지 않고, 음원을 미리 준비한 뒤 Timeline Signal에서 재생하는 방식으로 시작 시점을 맞췄다. 이후 시간 보정이 필요한 경우에는 음악을 기준으로 Timeline이 따라가도록 구성했다.

## Timeline과 FMOD 간 시간 편차

수정 후 다음 두 값을 비교했다.

- Timeline `PlayableDirector.time`
- FMOD `EventInstance.getTimelinePosition()`

측정 결과 두 시간 조회값 사이에 최대 20ms의 편차가 관측됐다.

Timeline의 `DSPClock`은 Unity 오디오 시스템의 시간을 기준으로 동작하지만, FMOD는 별도의 시간축을 사용한다. 두 시스템이 동일한 시간을 공유하지 않기 때문에 제한적인 편차가 발생한 것으로 판단했다.

## 결과

- Timeline Audio Track을 사용할 때 발생하던 초기 시작 편차를 줄였다.
- FMOD 음원을 사전에 로드하여 시작 지연을 줄였다.
- Timeline Signal을 통해 음악과 연출의 시작 흐름을 연결했다.
- 두 시간 조회값 사이에 최대 20ms의 편차가 남았지만 시간이 지나도 누적되지 않았다.

남은 편차는 실제 플레이와 연출에 미치는 영향이 제한적이었다. 또한 입력 판정은 Timeline 시간이 아닌 FMOD 음악 위치를 기준으로 처리하므로 판정 결과에도 직접적인 영향을 주지 않았다.

따라서 현재는 허용 가능한 수준으로 판단하고 후순위 개선 항목으로 유지했다.

## 회고

이번 문제를 통해 음악과 연출을 같은 위치에서 실행하는 것만으로 두 시스템이 항상 동기화되는 것은 아니라는 점을 알게 됐다. 각 시스템의 역할을 분리하고 음악을 기준으로 동작하도록 구성하면서 시작 시점의 편차를 줄일 수 있었다.

또한 남아 있는 문제는 편차의 크기와 누적 여부, 실제 플레이에 미치는 영향을 기준으로 판단하여 개선 우선순위를 정했다.
